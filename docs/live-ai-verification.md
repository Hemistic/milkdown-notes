# 2026-10-29 真实 OpenAI 验收

配置：OpenAI Platform 官方接口，`gpt-6-luna`，`reasoning_effort: medium`，通过 Milkdown 的 OpenAI Chat Completions provider 调用。模型与参数核对：[GPT-6 Luna 官方文档](https://developers.openai.com/api/docs/models/gpt-6-luna)。

## 接入

- 本地 Node 服务读取 `.env.local`，通过 `/api/ai` 转发增量文本；前端使用公开的 `createHttpAIProvider()`。
- 浏览器只获得模型名称、思考程度和是否配置；密钥不进入 Git、浏览器代码或测试报告。
- 取消会中断浏览器请求，并将 AbortSignal 传到上游。错误和正常完成分别传输；截断响应不能当作完整输出接受。
- 测试页 `/example/live-ai.html` 使用独立示例与内存文件接口，不读写用户笔记；只在点击运行时调用真实模型。

## 真实测试结果

7 项功能均已获得通过结果。Esc 修复后的整轮为 **7 / 7**；最终标题修复后的全量为 **6 / 7**，唯一中断项是首字前发生连接超时的“输出中取消”，该项随后独立重测通过。网络失败不计为通过。

| 项目                | 结果                                                     |
| ------------------- | -------------------------------------------------------- |
| 流式输出            | 多个增量片段持续到达；生成中及 diff 未确认时不保存       |
| 全部放弃            | 点击 diff 按钮后保留原文，没有文件写入                   |
| 重新改写            | 点击原生重试按钮，重发相同原始文档、选区与要求           |
| 全部接受            | 写入模型结果；撤销恢复原文，重做恢复接受结果             |
| 首字前 / 输出中取消 | 请求终止，后续文本不再进入编辑器，原文不变               |
| 断线后重试          | 收到真实输出后在客户端注入断线；再请求成功，旧错误清除   |
| Esc 保留草稿        | 进入部分结果 diff 审查；放弃后恢复原文，未确认内容不保存 |
| 异步状态            | 没有未处理拒绝或浏览器控制台错误                         |

七项测试中，接受/重试/撤销/重做合并为一项，两个取消阶段各一项。最终全量记录 8 次生成尝试：4 次完整输出、2 次取消、1 次主动注入断线、1 次连接超时。独立重测流中取消另发起 1 次请求，收到 2 个片段后成功中止。该全量的完整输出为 500–573 个增量片段，609–713 字符；完整请求首字约 1.8–2.1 秒，总耗时约 6.8–7.7 秒。它们是本次小样本观察，不是性能保证。

本轮先后遇到真实 `fetch failed` 和 `UND_ERR_CONNECT_TIMEOUT`，均在首个文本片段前发生，原文未变。被中断项目独立重测通过。没有隐藏网络失败，也没有添加自动重试循环；测试会将连接失败与功能断言区分报告。

## 本次发现与修复

Milkdown 的 `abortAICmd({keep:true})` 原本直接提交部分正文，Esc 因此绕过 diff。修复将它交给 `endStreamingCmd({diffReview:true})`，保留 AI 会话对审查的归属。Esc 和公开 `abort(true)` 现在都要求接受或放弃；`abort(false)` 仍恢复原文。增加固定数据回归，检查部分结果接受、Esc 放弃、保存回调和原文。

全文改写原先使用文本选区，保留了原来的标题节点外壳，模型返回的 `#` 会重复进入标题文字。现在使用 `AllSelection`，原生重新改写按钮也恢复完整文档选区。增加标题与正文的精确 Markdown 断言。正文变化通知只在已确认文档真正改变时发出，放弃未修改的草稿不再触发无效保存回调。
